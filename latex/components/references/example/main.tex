\chapter{Interprocess communication}
\section{Producer--consumer buffer}\label{sec:elements}

\begin{theorem}\label{thm:identity}
Suppose that the buffer starts empty, an insertion is permitted only when $n<N$, and a removal is permitted only when $n>0$. If every counter update is protected by mutual exclusion, the number of elements remains between zero and the capacity $N$.
\end{theorem}

\begin{equation}\label{eq:identity}
  0 \leq n_{\mathrm{buffer}} \leq N
\end{equation}

\begin{unipdcode}[language=Python,caption={Checking buffer availability},label={lst:identity}]
def can_consume(items):
    return items > 0
\end{unipdcode}

\begin{algorithm}[htbp]
  \caption{Removing an element from the buffer}
  \label{alg:identity}
  \KwInput{A non-empty shared buffer}
  \KwOutput{The oldest element}
  wait(\texttt{full})\;
  wait(\texttt{mutex})\;
  $x\gets$ remove element\;
  signal(\texttt{mutex})\;
  signal(\texttt{empty})\;
  \Return{$x$}\;
\end{algorithm}

The invariant in \cref{thm:identity}, expressed by \cref{eq:identity}, prevents overflow and underflow. \Cref{fig:reference} summarizes the flow, while \cref{tab:types,lst:identity,alg:identity} describe initialization and removal. Dijkstra's treatment of cooperating sequential processes includes the bounded-buffer construction used by this example \autocite{dijkstra-ewd123}.
